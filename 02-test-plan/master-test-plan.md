# Master Test Plan

## Project
Employee Training Management System

## 1. Purpose

The purpose of this project is to demonstrate a structured software quality assurance process by validating the functional behavior, access controls, API functionality, and critical workflows of an Employee Training Management System.

## 2. Test Objectives

The objectives are to:

- Verify that documented functional requirements are satisfied.
- Identify discrepancies between expected and actual behavior.
- Validate positive and negative user scenarios.
- Document defects with reproducible evidence.
- Perform regression testing after application changes.
- Validate API responses.
- Automate selected critical workflows.

## 3. Scope

Testing will include:

- User authentication
- Invalid authentication
- Employee creation
- Required-field validation
- Employee search
- Employee updates
- Employee deletion
- Training assignment
- Training completion status
- Access control

## 4. Testing Types

The project will include:

- Functional testing
- Negative testing
- Boundary testing
- Regression testing
- API testing
- Automated UI testing

## 5. Test Environment

Operating System:
Windows 11

Browsers:
Microsoft Edge
Google Chrome

Tools:

- Visual Studio Code
- Git
- GitHub
- Postman
- Playwright

## 6. Entry Criteria

Testing may begin when:

- Requirements are documented.
- The test environment is available.
- The application is accessible.
- Test data is available.

## 7. Exit Criteria

Testing will be considered complete when:

- Planned test cases have been executed.
- Significant defects have been documented.
- Failed tests have been reviewed.
- Regression testing has been completed.
- Automated tests have been executed.
- A final test summary report has been completed.

## 8. Defect Severity

### Critical
The defect prevents use of a critical system function or creates a serious security/data integrity issue.

### High
A major feature does not function correctly and no reasonable workaround exists.

### Medium
Functionality is affected, but a workaround exists.

### Low
Minor usability, cosmetic, or documentation issue.

## 9. Test Deliverables

The project will produce:

- Functional requirements
- Master Test Plan
- Manual test cases
- Requirements Traceability Matrix
- Defect reports
- API test collection
- Automated Playwright tests
- Test evidence
- Final Test Summary Report
